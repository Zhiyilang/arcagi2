# arcagi2 — 面向 ARC-AGI-2 的封闭变换 DSL 求解器

`arcagi2` 是一个零依赖（仅用 Python 标准库）的 [ARC-AGI-2](https://github.com/arcprize/ARC-AGI-2)
程序综合求解器，为 ARC Prize 2026 代码赛道构建。它在一条**封闭的网格变换库**中搜索，
并且只输出**能精确复现全部演示对**的程序——错误的程序永远不可能被误提交。

## 为什么选择封闭 DSL

ARC-AGI-2 的评测集是专门为击败程序综合而设计的：在官方 120 个公开评测任务中，
109/120 改变了连通组件数量，多数任务编辑超过 10% 的单元格。开放式搜索
（LLM 提议算子、自由形式代码）在这类任务上得分接近零。封闭库有不一样的性质：
**搜索是穷举式的而非启发式的**，因此每个输出的程序都可被证明与演示一致，
而且库小到可以靠读代码完成审计。

## 架构

```
arcagi2/
  grids.py     网格原语：几何、颜色映射、缩放、对称、重力
  objects.py   连通组件对象 + 对象级移动（整体下落、收集重排）
  patterns.py  图案补全：周期性修复、离群点修复
  dsl.py       变换库：不可变 (family, args) 记录 + apply()、
               enumerated_candidates()、second_stage_candidates()
  infer.py     从演示中**推断**参数（颜色映射、pad 目标、平移、放大倍数）
               ——绝不靠猜
  solver.py    搜索编排：深度 1 -> 深度 2 -> 深度 3 beam，双差异化尝试，
               截止时间有界
  taskio.py    任务 I/O、官方 either-attempt 计分、submission.json
solve.py       命令行：求解数据集并写出 submission.json
eval.py        离线断言套件（单元 + 推断 + 求解器 + 真实数据门 + 消融地板
               + 敌意 locale 安全）
ablations.py   家族电池：封闭式家族到底能覆盖公开集的多少？
               （`--dsl` 追加深度 2 枚举）
kaggle/        自包含 Kaggle 提交笔记本生成器
```

### 计分规则驱动设计

官方规则：**任一**尝试精确匹配即得分。因此精度比召回更重要——求解器输出
`attempt_1` = 最简单的一致程序，`attempt_2` = 次简单且**家族签名不同**的程序
（保证多样性）；当没有任何程序一致时，退回恒等加模态色填充，而不是乱猜。

### 搜索

1. **深度 1** —— 全部枚举候选 + 全部推断变换，对演示对做一致性过滤。
2. **深度 2** —— 幸存候选与策展式第二段组合（只收录真正出现在第二位的家族）。
3. **深度 3** —— 对部分组合做 beam 搜索，按 pair-0 优先拒绝排序。

每个阶段都有截止时间约束（`--budget`），运行必然以合法提交结束。

## 如实记录的实测结果

在官方公开评测集（120 个任务、167 个测试输出，数据来自
`arcprize/ARC-AGI-2`，Apache-2.0）上，本地 either-attempt 计分，
每任务 10 秒预算、深度 2：

| 指标 | 数值 |
|---|---|
| 找到一致程序的任务数（深度 ≤2 DSL） | 1 / 120 |
| 正确的测试输出数（任一尝试） | 0 / 167 |
| 断言通过数（`python eval.py`） | 163 / 163 |

**天花板是实测出来的，不是借口。** `ablations.py` 用与求解器相同的接受
规则（在演示对上拟合，只有**全部**复现才接受，然后预测）测量一个*封闭家族*
到底能覆盖公开集的多少：

| 家族 | 拟合任务数 | 正确的测试输出 |
|---|---|---|
| 恒等 | 0 / 120 | — |
| 水平翻转 | 0 / 120 | — |
| 垂直翻转 | 0 / 120 | — |
| 旋转 180° | 0 / 120 | — |
| 全局重染映射 | 0 / 120 | — |
| 带周期修复 | 1 / 120（`135a2760`） | 0 / 1 |

公开集里**没有一个**任务是纯重染、镜像、旋转或复制——该集合被对抗性地
过滤过，恰好剔除了封闭 DSL 能表达的那些家族。`eval.py` 把这六个数字钉成
回归地板：将来若有改动让某个平凡家族开始「拟合」任务，那是一致性检查的
bug，而不是进步。

**唯一通过过滤的结构母题。** 有 **48 / 120** 个任务的演示*输出*本身就已经
是规整的带周期结构（嵌套边框 + 内容遵循小二维周期）。这是集合里 40% 任务
真实存在的母题——但 `band_repair` 对其中绝大多数都不是正确的变换：演示输出
本来就是周期的，没有东西需要修复，输入→输出那一步是带结构的*生成*而非
*修复*。`ablations.py` 把母题计数与拟合计数分开报告，正是为了防止两者混淆。

唯一的一致 DSL 程序（任务 `135a2760`）能复现全部演示对，但无法泛化到测试
输入。本仓库的价值在于可审计的搜索、精确一致性保证（错误的程序永远不可能
被输出）、双尝试计分匹配，以及上面量化的负结果——而不是榜单分数。

## 复现这些数字

```bash
python ablations.py          # 廉价家族：约 8 秒出 6 个计数
python ablations.py --dsl    # 追加深度 2 枚举（约 12 分钟）
python eval.py               # 把上面每个数字都钉成断言
python solve.py --data data/evaluation --budget 10 --depth 2 \
    --report report.json --out submission.json
```

## 用法

```bash
python eval.py                       # 离线断言套件
python solve.py --data data/evaluation --budget 10 --depth 2 \
    --report report.json --out submission.json
python kaggle/build_notebook.py      # -> kaggle/submission.ipynb
```

## 数据

`data/evaluation/` 存放官方 `arcprize/ARC-AGI-2` 仓库的 120 个公开评测任务
（Apache-2.0）。Kaggle 隐藏测试集不在其中；笔记本在运行时自动发现平台提供的
任务文件。

## Kaggle 笔记本

`kaggle/build_notebook.py` 生成自包含的提交笔记本（`kaggle/submission.ipynb`，
离线、纯标准库）。Cell 1 会**先分类再索引** `/kaggle/input` 下的每个 JSON——
单任务文件、按 id 键控的多任务文件、任务列表、以及 `solutions` 文件
（`{task_id: [期望输出]}`）都会被区分开——因此任何版式假设都不会导致运行崩溃
（2026-10-24：solutions 文件曾被误读为多任务文件，原因是过滤式 `all()` 跳过了
列表型取值）。Cell 10 负责加载任务版式，并在快照附带 solutions 时挂载期望输出，
使本地评分覆盖全部任务而非仅公开子集。`kaggle/_test_discovery.py` 用合成的
混合版式快照对发现逻辑做回归测试；`python eval.py` 另断言笔记本每个代码单元
均可编译。
